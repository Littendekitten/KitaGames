KITAGAMES — FIRESTORE INDEX NOTES
=================================

The updated KitaGames build no longer uses collectionGroup('communityGames').
It reads from one top-level collection:

  /communityGames/{uid}__game-1
  /communityGames/{uid}__game-2
  /communityGames/{uid}__game-3

The public library query is a normal collection query with one equality filter:

  collection(db, 'communityGames')
  where('published', '==', true)
  limit(100)

Firestore Standard automatically maintains collection-scope single-field indexes
for ordinary equality queries. The 'published == true' filter uses that default
index. No collection-group index, composite index, index link, CLI command or
manual index creation is required.

If Firestore still shows an index error after uploading the new website, first
confirm that the new index.html has replaced the old one (search it for
"collectionGroup" — it should not appear). Then open Firestore → Indexes →
Single-field and confirm that indexing for 'published' on the communityGames
collection has not been disabled. The website no longer queries the legacy
users/{uid}/communityGames subcollections.
