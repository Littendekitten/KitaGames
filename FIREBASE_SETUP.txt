KITAGAMES — FIREBASE SETUP (NO COMMANDS)
========================================

The site is already connected to the Firebase web app configuration supplied
for project: kitagames (project ID: kitagames). You do not need to edit code or
run commands. Complete the console setup below once to turn on sign-in and
cloud saves.

1) ENABLE THE SIGN-IN METHODS
-----------------------------
1. Open https://console.firebase.google.com/
2. Select the kitagames project.
3. Open Build → Authentication.
4. Click Get started if Authentication has not been enabled yet.
5. Open the Sign-in method (or Sign-in providers) tab.
6. Enable Google. Choose a support email if Firebase asks for one, then Save.
7. Enable Email/Password, then Save.
8. Enable Anonymous, then Save. This powers “Continue as guest”.

2) AUTHORIZE YOUR GITHUB PAGES DOMAIN
-------------------------------------
1. In Authentication, open Settings → Authorized domains.
2. Add your GitHub Pages host, exactly in this form:
      YOUR-GITHUB-USERNAME.github.io
   Do not include https://, a repository path, or a trailing slash.
3. If you use a custom domain later, add that hostname too.

3) CREATE FIRESTORE DATABASE
-----------------------------
1. In the Firebase console, open Build → Firestore Database.
2. Click Create database.
3. Choose Production mode if asked. Do not select test mode for a public site.
4. Choose the database region carefully. Firestore database location is not
   something you should casually change after creation.
5. Finish creating the database.

4) PUBLISH THE PRIVATE PROFILE RULES
------------------------------------
1. Open Firestore Database → Rules.
2. Open FIRESTORE_RULES.txt from this website folder.
3. Copy the full rules between the “COPY” markers.
4. Paste them into the Firebase Rules editor.
5. Click Publish.
6. Do not use public read/write rules. The included rules let each account
   read/write only its own users/{uid} profile document.

5) UPLOAD THE WEBSITE TO GITHUB PAGES
-------------------------------------
1. Extract KitaGames-GitHub-Pages.zip on your computer.
2. Open your GitHub repository in the browser.
3. Use Add file → Upload files.
4. Upload every file and folder from the extracted kitagames folder. Keep the
   assets folder in the same place as index.html. Do not upload only index.html.
5. Commit the upload to the main branch.
6. Open Settings → Pages. Choose Deploy from a branch, branch main, folder
   /(root), then Save.
7. Wait for GitHub Pages to publish. The website address appears in Settings
   → Pages.

6) CHECK SIGN-IN AND SAVES
--------------------------
1. Visit your published GitHub Pages site using its https:// address.
2. Click Sign in.
3. Try Continue as guest first. A guest profile should be created in Firebase
   Authentication and its private profile should appear in Firestore under
   users/{the guest UID}.
4. Add a favorite or finish a game to create a personal best. Refresh the page
   and check that the data remains.
5. Open Sign in again and link the guest save to Google, or create an email and
   password account. Google/email sign-in can be used on another device to
   retrieve the same cloud profile.

IMPORTANT DETAILS
-----------------
- The Firebase JavaScript SDK is loaded directly from Google's CDN. No build
  tool, terminal, npm, or local server is required.
- The app uses Firebase Authentication and Cloud Firestore. Analytics is not
  initialized; the measurement ID is retained in the config only.
- The Firebase web API key in index.html is expected to be visible in a web
  app. It is not a private key. Keep Firestore locked down with the supplied
  security rules and never add service-account credentials to this folder.
- Guest accounts are anonymous Firebase accounts. They are useful for casual
  play, but linking the guest account to Google is the safest way to keep the
  save if you later switch browsers/devices or clear local site data.
- If Google sign-in reports “unauthorized domain”, repeat step 2 and ensure
  you added only the hostname shown in the address bar.
- If sign-in works but cloud saves do not, check that Firestore exists and the
  latest FIRESTORE_RULES.txt rules have been Published.
