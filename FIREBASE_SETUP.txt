KITAGAMES — FIREBASE SETUP (NO COMMANDS)
========================================

The site already contains the Firebase web configuration for project
"kitagames". The community creator stores each HTML game directly in Cloud
Firestore. No custom server, backend, Firebase Storage or Cloud Functions are
required.

1) ENABLE SIGN-IN PROVIDERS
---------------------------
1. Open https://console.firebase.google.com/ and select the kitagames project.
2. Open Build → Authentication → Get started (if needed).
3. Enable Google and choose a support email if asked.
4. Enable Email/Password.
5. Enable Anonymous if you want visitors to use guest play.

2) AUTHORIZE YOUR GITHUB PAGES DOMAIN
-------------------------------------
1. In Authentication, open Settings → Authorized domains.
2. Add your GitHub Pages hostname, for example:
      YOUR-GITHUB-USERNAME.github.io
   Do not include https://, a repository path, or a trailing slash.
3. Add your custom domain too if you use one later.

3) CREATE FIRESTORE
-------------------
1. Open Build → Firestore Database.
2. Click Create database and choose Production mode.
3. Choose a database region and finish creating the database.

4) PUBLISH THE FIRESTORE SECURITY RULES
----------------------------------------
1. Open Firestore Database → Rules.
2. Open FIRESTORE_RULES.txt from this website folder.
3. Copy the full rules between the COPY markers into the Rules editor.
4. Click Publish.
5. These combined rules keep account profiles private, allow anyone to read
   only published community games, let each owner read their private drafts,
   and enforce exactly three reusable game slots per account. Do not replace
   them with public read/write rules.

5) COMMUNITY LIBRARY INDEX
--------------------------
The current website uses a top-level /communityGames collection and a normal
collection query filtered by published == true. Firestore's default
collection-scoped single-field index handles this automatically, so no custom
collection-group index, composite index, or manual index creation is required.
See FIRESTORE_INDEXES.txt if an older browser build still displays the old
collection-group index message.

6) USE THE COMMUNITY CREATOR
----------------------------
1. Open the published KitaGames site.
2. Sign in with Google or email/password. Guest accounts can play but cannot
   create or publish games.
3. Scroll to Community → Make a game.
4. Enter a title and short description.
5. Paste a complete self-contained HTML game, or upload one .html/.htm file.
6. Preview the game. Choose whether to keep it private or publish it.
7. Save it to Firestore. Each account has three slots; edit a saved game or
   delete one to free a slot.

7) UPLOAD THE WEBSITE TO GITHUB PAGES
-------------------------------------
1. Extract KitaGames-GitHub-Pages.zip on your computer.
2. Open your GitHub repository in the browser and choose Add file → Upload files.
3. Upload every file and folder from the extracted kitagames folder. Keep the
   assets folder beside index.html. Do not upload only index.html.
4. Commit the upload to the main branch.
5. Open Settings → Pages. Choose Deploy from a branch, branch main, folder
   /(root), then Save.

8) CHECK SIGN-IN AND SAVES
--------------------------
1. Visit your site using its https:// GitHub Pages address.
2. Test Google/email sign-in and guest play.
3. Add a favorite or finish a game, refresh, and confirm the private profile
   syncs in Firestore under users/{your-auth-uid}.
4. Sign in with Google/email, publish a small test game, then open the site in
   a signed-out browser window to confirm it appears in Community.
5. Try creating a fourth game: the site should stop you, and Firestore Rules
   independently reject any attempt to write a fourth slot.

COMMUNITY GAME FORMAT
---------------------
- One .html/.htm file per game, or paste a complete self-contained HTML page.
- Maximum 80,000 characters per game.
- Inline HTML/CSS/JavaScript is supported. Small images may be embedded as
  data URLs. External scripts/resources and network APIs are blocked by the
  game Content Security Policy; popups and top-level redirects are disabled
  by the iframe sandbox. A sandbox is not a full malware scanner.
- Private drafts are visible only to their owner. Published games are public.
- HTML source is stored in Firestore documents, not Firebase Storage.
- The three-slot cap is enforced by fixed document IDs in Firestore Rules,
  not just by a counter in the website.

IMPORTANT DETAILS
-----------------
- Firestore is a hosted service and normal Firebase quotas/pricing can apply
  for reads, writes, stored data and data transfer. No custom backend does not
  mean unlimited usage or guaranteed zero cost. Review Firebase usage and set
  budget alerts in Google Cloud if appropriate.
- The Firebase JavaScript SDK loads directly from Google's CDN. No terminal,
  npm, build tool or command-line setup is required.
- The Firebase web API key in index.html is a public client identifier, not a
  private key. Never add a Firebase Admin service-account key to this site.
- Guest accounts use anonymous Firebase Auth. Link a guest to Google or switch
  to a permanent Google/email account before using the creator.
- Analytics is not initialized in this build; the measurement ID remains in
  the Firebase config only.


7) IF THE OLD COLLECTION-GROUP INDEX WARNING STILL APPEARS
-----------------------------------------------------------
The current index.html uses collection(db, 'communityGames') with only a
where('published', '==', true) equality filter and limit(100). It does not use
collectionGroup(). Firestore automatically maintains the normal collection-
scoped single-field index needed for that query.

1. Replace the old website files with every file from the newest ZIP.
2. Publish the new FIRESTORE_RULES.txt in Firebase Console.
3. Hard-refresh the website (Ctrl+Shift+R on Windows/Linux, Cmd+Shift+R on Mac),
   or open it in a private/incognito window.
4. Check the browser's loaded index.html source for the text
   "collectionGroup". It should not be present.
5. Confirm that the 'published' field has not been exempted from automatic
   indexing for the top-level communityGames collection.

Existing player-made games from the older nested layout are copied into the
new top-level collection the next time their owner signs in. Publish the new
rules before signing in so the migration can read and remove the legacy copy.
