KITAGAMES COMMUNITY CREATOR — RULES FOR UPLOADED GAMES
=======================================================

ACCOUNT RULES
------------
1. You must be signed in with Google or email/password to create, save, edit,
   or publish community games. Guest accounts can play games but cannot publish.
2. Each account gets three game slots: game-1, game-2 and game-3.
3. A slot can contain one game. Editing a game does not use another slot.
4. Delete a game to free its slot for a replacement. There is no fourth slot.
5. You choose whether a saved game is a private draft or public.
6. Public games can be played by anyone who visits KitaGames. Private drafts
   are visible only to the account that created them.

FILE AND CODE RULES
-------------------
1. Upload one .html or .htm file, or paste a complete self-contained HTML game.
2. The maximum source length is 80,000 characters per game.
3. HTML, inline CSS and inline JavaScript are supported.
4. Add small images as data URLs inside your HTML if needed.
5. External JavaScript, external stylesheets, network requests, embedded
   frames, forms, objects, plug-ins and outbound connections are blocked when
   a community game is previewed or played.
6. Games must work without a server, build step, package manager or external API.
7. Do not include passwords, API secrets, private data or personal information.

SAFETY AND COMMUNITY
--------------------
1. Community games are player-created and are not official KitaGames games.
2. Do not upload malware, deceptive content, harassment, hate, explicit sexual
   content, violent threats, scams, or content that violates other people's
   rights.
3. Do not impersonate another creator or use artwork/code without permission.
4. The sandbox separates the game from the main site and blocks network access,
   but users should still inspect unfamiliar game content and report abuse.
5. Publishing makes the game's title, description, creator display name and
   HTML source publicly readable in Firestore. Do not include private details.

PLAY CONTROLS
-------------
- Use the controls provided inside each player-created game.
- Use KitaGames' Fullscreen button or press F to fullscreen the game area.
- Press Escape to leave fullscreen.
- Use Back to return to the game library.

DATA AND STORAGE
----------------
- Game HTML is stored directly in Cloud Firestore; Firebase Storage is not used.
- Deleting a game removes its Firestore game document and frees the slot.
- Firestore Security Rules, not a browser-only counter, enforce slot ownership
  and the three-game maximum.
- The site has no separate server or custom backend.


PUBLIC LIBRARY, PERSISTENCE AND SHARING
--------------------------------------
- Published games are stored in the top-level Firestore collection as:
  communityGames/{uid}__game-1, communityGames/{uid}__game-2 or
  communityGames/{uid}__game-3.
- The Discover page queries the top-level communityGames collection where
  published == true. This reloads from Firestore after refresh and uses the
  normal collection-scoped single-field index (no collection-group index).
- The public shelf also uses a Firestore realtime listener. New publications,
  edits, unpublishing and deletions appear for visitors while the site is open.
- Each published game has a Share button. It copies a permanent KitaGames URL
  containing the creator UID and fixed game slot, for example:
      https://YOUR-USERNAME.github.io/kitagames/?play=FIREBASE_UID/game-1
  Anyone opening that URL can load the public Firestore document and play it.
  Refreshing the shared URL opens the same game again.
- The direct link reads only one game document and verifies published == true.
  Private drafts cannot be opened by other users, even if they guess the URL.
- If a creator unpublishes or deletes a game, its public card disappears and
  its old shared URL stops opening the game.
- Firestore's public collection query and direct document reads require the
  public read rules in FIRESTORE_RULES.txt. The public listing is limited to
  100 games per query in this build.
- Share URLs contain the Firebase Auth UID and slot identifier, not the
  creator's email address or private HTML draft content.

- Older nested creator documents are copied to the top-level collection when
  their owner first signs in on the updated build, then the legacy copy is deleted.
